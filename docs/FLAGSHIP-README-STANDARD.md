# Flagship README standard

Flagship repositories keep their technical documentation intact and add a shared MojeAlterego project-status block near the top.

## Required status block

```md
> [!IMPORTANT]
> **MojeAlterego project status:** `PROTOTYPE`
> **Domain:** Android / AI / Agents
> **Verification:** concise evidence boundary
> **Status policy:** link to the shared project-status model
```

## Required README sections

A flagship repository should document, where applicable:

1. project identity and problem statement,
2. declared maturity status,
3. verified scope,
4. architecture,
5. repository layout,
6. local setup,
7. build/test commands,
8. CI/deployment path,
9. security and secrets,
10. known limitations,
11. verification evidence,
12. license.

## Technical honesty

Do not use `PRODUCTION`, `production-ready`, `deployed` or equivalent wording unless the repository contains or links to verification evidence that supports the claim.

Screenshots, renders and conceptual visuals must not be presented as proof of implemented functionality.
